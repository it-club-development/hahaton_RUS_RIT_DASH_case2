# Мотив · Веб-отчётность

`frontend/` содержит внешний React + TypeScript интерфейс. `WebOtchet/` содержит ASP.NET Core API и миграции EF Core. При локальном запуске ASP.NET Core отдаёт собранный фронтенд и API с одного адреса.

## Запуск на Windows

1. Установите Node.js 24 LTS с npm, .NET 10 SDK и Docker Desktop. Запустите Docker Desktop и дождитесь запуска движка.
2. Откройте PowerShell в корне проекта. Скопируйте файл настроек.

   ```powershell
   Copy-Item .env.example .env
   notepad .env
   ```

3. Заполните `WEBOTCHET_DB_PASSWORD` и `WEBOTCHET_ADMIN_PASSWORD` разными паролями длиной от 12 символов. Для пароля базы используйте латинские буквы, цифры, дефис или подчёркивание. Для локального файла используйте по одной записи на строку без кавычек. Сохраните файл.
4. Запустите проект.

   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1
   ```

5. Откройте http://localhost:5126/. Войдите с логином и паролем из настроек администратора. При первом запуске сервер применит миграции и создаст администратора, если администраторов ещё нет. Изменение файла настроек после создания учётки не меняет её пароль.

Администратор создаёт и редактирует аварии. Инженер просматривает отчёт и скачивает CSV. Серверные роли взяты из исходного `WebOtchet`. Выгрузка формируется в браузере из отфильтрованных записей API. Локальные записи из демонстрационного фронтенда не импортируются.

Для остановки API нажмите Ctrl+C. Для остановки базы выполните `docker compose stop`. Данные сохраняются в томе Docker. Порт базы на хосте по умолчанию 3307. В контейнере используется 3306.

Для работы над интерфейсом оставьте API запущенным и в другом окне выполните в `frontend/` команду `npm.cmd run dev`. Vite проксирует `/api` на порт 5126.

В этой сборке сохранена версия MariaDB, указанная в исходном серверном коде (12.3.3). Совместимость с MariaDB 10.1 требует отдельной проверки.
