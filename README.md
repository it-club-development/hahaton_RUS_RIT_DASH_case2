# Мотив — «Веб отчётность»

**Кейс №02 · сборка 2.1 · руководство для эксперта**

Приложение ведёт журнал аварий сети мобильной связи. Дежурный регистрирует и закрывает аварии, инженер просматривает журнал, администратор управляет записями и пользователями. В отчётности доступны фильтры по периоду, направлению, техническому центру и статусу, сортировка по дате, сводки и выгрузка CSV.

## Стек и устройство проекта

| Компонент | Технологии и файлы |
|---|---|
| Веб-интерфейс | React 18, TypeScript 5.9, Vite 7, CSS. Исходники в `frontend/src/` |
| API и правила работы с авариями | C#, ASP.NET Core на .NET 10, REST/JSON. Код в `WebOtchet/Controllers/` и `WebOtchet/Services/` |
| Хранение данных | MariaDB 10.1.48, EF Core 10, провайдер Doka. Конфигурация модели в `WebOtchet/Data/`, история схемы в `WebOtchet/Migrations/` |
| Сборка и запуск | Docker, Docker Compose v2. Настройки в `Dockerfile` и `compose.yaml` |

Контейнер `app` отдаёт React и обслуживает API по одному адресу. Он подключается к контейнеру `db` по адресу `db:3306`. Compose ждёт готовности базы, затем приложение применяет миграции. Данные MariaDB и ключи сессий сохраняются в отдельных томах. Сайт по умолчанию доступен на хосте по адресу `http://localhost:5126/`.

## Как запустить с чистой базой

### 1. Подготовьте Docker

Для Windows запустите Docker Desktop в режиме Linux-контейнеров. Для Debian-подобного Linux нужны Docker Engine и плагин Docker Compose v2. Для первой сборки потребуется доступ к реестрам образов, npm и NuGet. Node.js и .NET SDK устанавливаются при сборке образа.

Проверьте, что Docker доступен и в выводе `docker version` есть раздел Server.

```text
docker version
docker compose version
```

### 2. Откройте папку проекта

Распакуйте архив. Откройте терминал в папке, где лежат `compose.yaml`, `Dockerfile` и этот README. На Windows можно открыть эту папку в Проводнике, ввести `powershell` в адресной строке и нажать Enter.

### 3. Задайте настройки

Откройте файл `.env` в этой папке. Для чистой установки создайте его в текстовом редакторе, если его ещё нет. На Windows выполните `notepad .env`. При сохранении проверьте, что имя файла — именно `.env`.

Добавьте следующие строки. Сохраните имя `admin` либо задайте свой логин. Впишите три разных пароля после знаков равенства.

```dotenv
WEBOTCHET_DB_PASSWORD=
WEBOTCHET_DB_ROOT_PASSWORD=
WEBOTCHET_ADMIN_USER=admin
WEBOTCHET_ADMIN_PASSWORD=
```

| Переменная | Назначение |
|---|---|
| `WEBOTCHET_DB_PASSWORD` | Пароль пользователя MariaDB `webotchet`, с которым приложение обращается к БД |
| `WEBOTCHET_DB_ROOT_PASSWORD` | Пароль администратора MariaDB `root` |
| `WEBOTCHET_ADMIN_USER` и `WEBOTCHET_ADMIN_PASSWORD` | Логин и пароль для первого входа в приложение |

Выберите пароли длиной от 12 символов. Для запуска используйте латинские буквы, цифры, дефис и подчёркивание. Храните `.env` локально. Полный список настроек приведён в `.env.example`. Часовой пояс по умолчанию — `Asia/Yekaterinburg`.

### 4. Соберите и запустите приложение

```text
docker compose config --quiet
docker compose up -d --build
docker compose ps
docker compose logs -f app
```

Если первая команда завершилась без вывода, конфигурация прошла проверку. При первом запуске Docker скачивает образы и собирает приложение. В списке сервисов база `db` должна быть `healthy`, а `app` — запущен. Дождитесь строки `Now listening on` в логах. Нажмите **Ctrl+C**, чтобы выйти из просмотра логов.

### 5. Войдите в приложение

Откройте [http://localhost:5126/](http://localhost:5126/). Для чистой базы используйте логин из `WEBOTCHET_ADMIN_USER` (обычно `admin`) и пароль из `WEBOTCHET_ADMIN_PASSWORD`.

Для остановки обоих контейнеров выполните `docker compose stop`. Для повторного запуска выполните `docker compose up -d`. Данные остаются в томе MariaDB.

## Обновление существующей базы

Перед обновлением сделайте резервную копию. Используйте прежнее имя проекта Compose, чтобы подключить существующий том MariaDB 10.1. Сохраните действующий `.env` и добавьте в него `WEBOTCHET_DB_ROOT_PASSWORD` с текущим паролем `root`. Если root-пароль в старой конфигурации совпадал с паролем пользователя `webotchet`, укажите это действующее значение. Изменение `.env` само по себе пароли в существующем томе не меняет. Для входа на сайт используйте существующую учётную запись.

При переносе с другой основной версии MariaDB используйте SQL-дамп и новый том, предварительно проверив совместимость на копии базы. Для обновления с сохранением данных избегайте команды `docker compose down -v`, которая удаляет тома проекта.

## Сценарий приёмки

| Шаг | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Войдите как администратор. Создайте дежурного и инженера в разделе «Пользователи». | Пользователи созданы с выбранными ролями и могут войти. |
| 2 | Под дежурным создайте аварию с отметкой «НВ», количеством БС `5` и прерыванием связи `00:10:00`. | Запись открыта, длительность растёт, общий простой составляет `00:50:00`. |
| 3 | Под администратором создайте вторую открытую аварию. Под дежурным закройте её из отчёта. | Появляется подтверждение, после закрытия фиксируются время окончания и длительность. |
| 4 | Найдите первую аварию с помощью фильтров периода, направления и статуса. Выгрузите CSV. | CSV содержит записи по всем выбранным фильтрам за указанный период. При наличии более 20 записей первая страница показывает 20, а «Ещё» раскрывает следующие строки. |
| 5 | Войдите под инженером и откройте карточку. | Карточка доступна для чтения, прав на изменение нет. |
| 6 | Проверьте сохранение данных после `docker compose stop` и `docker compose up -d`. | Аварии и созданные пользователи остаются в базе. |

## Особенности схемы и статус проверки

- Открытая авария имеет нулевую дату в `END_TIME`. API передаёт её как `null`. `NUMB_RBS` хранится как `INT`, значение `0` обозначает сектор «С». Правило расчёта простоя для сектора в ТЗ не задано, поэтому значение для него остаётся неопределённым.
- `KATEG` имеет тип `TINYINT`. `COMMON_PROSTOY` имеет тип `TIME`. При превышении предела `838:59:59` поле равно `NULL`, а точное значение в секундах хранится в `COMMON_PROSTOY_SECONDS` и используется в отчётах и CSV. `ID` и `CreatedByUserId` служат для идентификации записи и проверки прав.
- Для сборки проекта проверены .NET, TypeScript и Vite, конфигурация Compose и генерация SQL миграций. Полный прогон на Debian-подобном Linux с MariaDB 10.1.48 и Chrome 75.0.3770.100 x64 остаётся этапом приёмки. В Chrome 75 часть отступов в отчёте может отличаться из-за `gap` во Flexbox.

## Если запуск остановился

| Сообщение или симптом | Что проверить |
|---|---|
| `WEBOTCHET_DB_ROOT_PASSWORD is missing a value` | Убедитесь, что файл называется `.env`, находится рядом с `compose.yaml`, а после знака равенства указан пароль. |
| `address already in use` | Освободите порт или задайте в `.env` другой `WEBOTCHET_APP_PORT` либо `WEBOTCHET_DB_PORT`. При изменении порта приложения откройте новый адрес в браузере. |
| Сайт недоступен или приложение перезапускается | Выполните `docker compose ps`, `docker compose logs --tail=100 app` и `docker compose logs --tail=100 db`. |
| Настройки входа поменялись, а прежняя база сохранилась | Используйте пароль существующей учётной записи. Начальные настройки администратора применяются при его создании. |

Справка по настройке окружения и командам доступна в [документации Docker Compose](https://docs.docker.com/compose/).
