# Мотив · исправления v1.2

## Запуск

Распакуйте архив в отдельную папку. В корне настройте локальный `.env` по `.env.example`. Для подключения существующей базы используйте прежние настройки и тот же проект Docker Compose. Запустите Docker Desktop и выполните:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\start-local.ps1
```

Приложение открывается на http://localhost:5126/. Для запуска нужны Node.js с npm и .NET 10 SDK.

## Существующая база

Перед обновлением сохраните резервную копию. Числовые значения в исправленной версии: 0 — администратор, 1 — инженер, 2 — дежурный. Для базы из версий до исходной v1.2, где 1 уже означало «инженер», перенос ролей не нужен.

Если исходная v1.2 уже создавала пользователей или меняла роли, проверьте назначение всех затронутых учётных записей перед запуском исправленной сборки. В исходной v1.2 число 1 означало дежурного, а 2 — инженера. Для базы, которую обновляли с прежних версий, рядом могут находиться записи с разным происхождением. В остановленном приложении действующие роли сверяют по учётным записям и меняют адресно, по идентификатору. Пароли и хеши для сверки не нужны.

```sql
SELECT ID, USERNAME, ROLE FROM USERS ORDER BY USERNAME;
-- После проверки роли конкретного пользователя:
UPDATE USERS SET ROLE = 2 WHERE ID = '<UUID подтверждённого дежурного>';
UPDATE USERS SET ROLE = 1 WHERE ID = '<UUID подтверждённого инженера>';
```

Оставьте администраторам значение 0. Не применяйте массовый обмен 1 и 2 к смешанной базе.

Миграция автора допускает NULL для исторических аварий. Если прежний запуск уже прервался внутри миграции, сначала проверьте состояние схемы по резервной копии и журналу миграций. Новая сборка не удаляет частично созданные объекты автоматически.

## Поведение приложения

- Дежурный создаёт аварии и может менять или удалять свои. Администратор управляет всеми записями, включая записи без автора. Инженер просматривает отчёт.
- Редактирование сохраняет автора. Чужая запись возвращает 403, отсутствующая — 404. Удаление пользователя, связанного с авариями, возвращает 409 и сохраняет историю.
- При смене роли, имени или удалении аккаунта прежняя cookie отклоняется при следующем запросе. Сброс пароля администратором задаёт пароль для будущих входов. Самостоятельная смена пароля завершает текущую сессию.
- В интерфейсе доступны управление пользователями, смена и сброс пароля, темы и подтверждение удаления.

Архив содержит шаблон настроек. Если исходный архив с действующими паролями уже был передан другим людям, смените эти пароли отдельно.

## Проверка после запуска

Проверьте обновление на копии базы с историческими авариями. Войдите администратором, инженером и двумя разными дежурными. Проверьте создание дежурным, редактирование собственной аварии, отказ на чужой и сохранение автора при редактировании администратором. Проверьте запрос к отсутствующей аварии, удаление автора с историей, смену роли при активной сессии и запрос обновления пользователя без поля role.
